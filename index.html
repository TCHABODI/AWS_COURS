Architecture Big Data - Vue d'ensemble

Cette architecture 100% serverless collecte en temps reel les flux de donnees emis par des milliers de capteurs IoT industriels via des requetes HTTP POST. L'ensemble de l'infrastructure est automatisee par AWS CloudFormation.

Strategie de partitionnement S3 (Data Lake)

Les fichiers JSON bruts sont stockes selon un schema Hive-compatible qui permet des requetes performantes avec AWS Athena ou Apache Spark. 

s3://{environment}-iot-datalake/
└── raw-zone/
    └── year=2026/
        └── month=06/
            └── {request_id}.json

Chaque fichier contient le payload complet de la requete avec tous les enregistrements du batch.

Schema DynamoDB - Feature Store

Chaque execution de la Lambda genere une entree dans la table {environment}-iot-feature-store : 

{
  "request_id":      "abc-123-...",
  "timestamp":       "2026-06-07T10:00:00.000Z",
  "s3_path":         "s3://bucket/raw-zone/year=2026/month=06/abc.json",
  "avg_temperature": 81.4,
  "error_count":     2,
  "record_count":    4
}

Securite - Acces a la documentation via CloudFront OAC

Acces direct S3 bloque : Toute tentative d'acces a l'URL S3 directe retourne une erreur HTTP 403 Access Denied. Le bucket de documentation a le Block Public Access active.

L'acces est autorise uniquement via la distribution CloudFront grace au mecanisme OAC (Origin Access Control) :

  1. CloudFront signe chaque requete vers S3 avec AWS Signature V4 (SigV4).
  2. La Bucket Policy autorise uniquement les requetes dont l'ARN source correspond a la distribution CloudFront declaree.
  3. Les utilisateurs accedent au site via HTTPS uniquement (redirection forcee).
# Condition de la Bucket Policy (extrait CloudFormation)
Condition:
  StringEquals:
    AWS:SourceArn: "arn:aws:cloudfront::ACCOUNT_ID:distribution/DISTRIB_ID"

Commande CLI - Upload de la documentation

Pour uploader ce fichier index.html dans le bucket de documentation : 

aws s3 cp index.html s3://{environment}-tech-doc/index.html \
  --content-type "text/html; charset=utf-8"

Verification de la presence du fichier dans le bucket :

aws s3 ls s3://{environment}-tech-doc/
